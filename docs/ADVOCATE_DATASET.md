# NYAYAI Synthetic Advocate Dataset

This document describes the **500 synthetic advocate profiles** and their **5,000
linked historical case files** used by the NYAYAI legal demonstration.

The committed dataset is a clean, indexed representation of the **existing**
advocates the application already uses. It is **not** a newly generated or second
set of lawyers.

## Sources of truth

| File | Role |
| --- | --- |
| `server/data/advocate-profiles.json` | The 500 advocate profiles (generated by `server/scripts/seedDemoCorpus.mjs`). |
| `server/data/corpus-generation-manifest.json` | Per-case ground truth for all 5,000 cases (`case_id`, docket, advocate, matter, area, court, year, status). |
| `server/data/advocates/advocates-500.json` | **This dataset** — a committed export of the two sources above (camelCase schema). |
| `server/fixtures/legal-corpus/advocate-cases/*/case-*.pdf` | The 5,000 rendered `case_history` PDFs. Machine-generated from the same data. |

## Exact counts (post-validation)

- **Advocates:** 500 (`advocate-001` … `advocate-500`).
- **Cases per advocate:** exactly **10** each.
- **Total historical cases:** **5,000** (`CASE-00001` … `CASE-05000`).
- **Duplicate advocate IDs:** 0. **Duplicate case IDs:** 0. **Orphan cases:** 0.
- Every case belongs to exactly one advocate; every advocate owns exactly 10 cases.

Validated by:

- `server/scripts/validateAdvocatesDataset.mjs` — **18/18 checks pass**.
- `server/tests/dataset-validation-tests.mjs` — **9/9 tests pass**.

## How advocates are represented

Each advocate in `advocates-500.json` (`dataset.advocates[]`) carries the profile
fields already used by the demo, re-presented under a documented camelCase schema:

- `advocateId`, `advocateIndex`, `name`, `gender`
- `email` — a clearly synthetic demo address (`@law.in`, `@juris.in`, `@lex.in`, `@legal.in`)
- `barRegistration`, `firm`, `partner`
- `primaryPracticeArea` / `primaryPracticeLabel` and `practiceAreas` (each advocate lists 3 areas)
- `jurisdiction` (= state), `state`, `city`
- `yearsExperience`, `enrolledYear`, `experienceLevel` (derived: Partner / Senior Advocate / Experienced Advocate / Advocate)
- `languages`, `niches`, `averageCasesPerYear`, `successProxy`
- `syntheticStatus` (`SYNTHETIC_DEMONSTRATION_DATA`), `sourceType` (`synthetic`)
- `caseCount` (always 10), `cases` (the advocate's 10 `CASE-#####` ids), `statistics`

Derived fields (`experienceLevel`, `statistics`, `caseCount`, `cases`) are computed
from the existing profile and corpus-manifest fields; no advocate data is invented.

**Excluded on purpose:** phone numbers, passwords/hashes, tokens, verification
codes, credentials, private client/consultation data, and any reference to the
live file/vector stores. This keeps the committed dataset safe for demonstration.

> Field-name mapping (source → dataset): `advocate_id → advocateId`,
> `bar_registration → barRegistration`, `practice_areas → practiceAreas`,
> `years_experience → yearsExperience`, `enrolled_year → enrolledYear`,
> `average_cases_per_year → averageCasesPerYear`, `success_proxy → successProxy`,
> `synthetic_status → syntheticStatus`, `source_type → sourceType`.

## How case history connects to advocates

- A docket number `NY-DEMO/{AREA}/{CITY}/{YEAR}/{5-DIGIT-SEQ}` and a canonical
  `case_id` (`CASE-#####`) uniquely identify every historical case.
- Each case belongs to exactly one advocate via `advocate_id`; each advocate owns
  exactly 10 `case_history` files that render as `advocate-cases/{advocate}/case-#####.pdf`.
- The same `advocate_id` keys the profiles, the case manifest, and the ingested
  vector-DB metadata, so a case can always be traced back to its advocate (and
  vice-versa).

## How the dataset is used

**Advocate discovery.** `GET /api/v1/advocates` returns the directory with
persisted profile evidence (`practiceAreas`, `verificationStatus`,
`verifiedCaseCount`, fees, jurisdictions). Recommendations
(`GET /api/v1/advocates/recommendations/:caseId`) score advocates from real
directory fields — practice area, jurisdiction, court, experience, budget — and
never fabricate ratings or outcomes.

**Semantic retrieval of historical evidence.** The 5,000 case PDFs are chunked
into 28,030 chunks, embedded (real Ollama `nomic-embed-text`, 768-d when
configured), indexed in the C++ vector DB, and surfaced by
`POST /api/v1/legal/search`, `advocate-cases`, and `rag`. Every retrieved chunk
carries `advocate_id`, `case_id`, docket `case_number`, practice area, court,
year, and status, so RAG answers are grounded in traceable synthetic history.

**Co-Counsel / precedent research.** `POST /api/v1/ai/co-counsel/…` retrieval
and precedent research query the same corpus, tagging results `synthetic` and
never asserting the cases are real judgments.

## Synthetic-data warning

- All advocates and every one of the 5,000 cases are **synthetic demonstration
  data** (`SYNTHETIC_DEMONSTRATION_DATA`). Names, firms, bar numbers, parties,
  citations, amounts, and outcomes are machine-generated.
- Synthetic cases **must not** be presented, cited, or relied upon as real court
  judgments or real precedent.
- Emails/addresses are fabricated; do not contact them or treat them as real.

## Safe-for-demo fields

Safe to display/export: `advocateId`, `name`, `barRegistration`, practice areas,
jurisdiction/state/city, `yearsExperience`, `enrolledYear`, `experienceLevel`,
`languages`, `niches`, `firm`, `partner`, `averageCasesPerYear`, `successProxy`,
`caseCount`, `cases`, `statistics` (area/court/status/year aggregates), and the
synthetic `email`. Not present by design: passwords, hashes, tokens, verification
codes, credentials, phone numbers, private client/consultation records, or any
reference to live infra secrets.

## Regenerating the dataset

```bash
# From server/  (requires the existing generated sources)
node scripts/exportAdvocatesDataset.mjs      # writes data/advocates/advocates-500.json
node scripts/validateAdvocatesDataset.mjs    # 18/18 checks, non-zero exit on failure
node tests/dataset-validation-tests.mjs      # 9/9 checks, non-zero exit on failure
```

The export is deterministic and read-only over its sources; it never regrows the
5,000-case corpus.
